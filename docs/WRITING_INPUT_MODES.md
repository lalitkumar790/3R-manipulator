# 3R Robot: English, Hindi, and Draw/Scribble

## Web UI

The **Writing input mode** selector has:

- **English**: the existing A–Z vector-stroke glyph font.
- **हिन्दी**: shape the text using a Devanagari browser font and follow its visible **glyph contours**. This is outline/tracing, not handwriting-centerline conversion. The browser uses Noto Sans Devanagari if loaded, otherwise available system fonts. Shape may vary by font and ligature shaping.
- **Draw / Scribble**: a pointer/touch/stylus drawing canvas, **Undo stroke** and **Clear drawing**. Supports multiple ordered continuous strokes. The planner preserves aspect ratio while proportionally fitting to the nominal writing plane.

All inputs feed the same 3R IK path-planning stage in \`src/path-planner.js\` (English retains its existing vector font generator). Each target includes \`{x,y,q:[radians],lift,ink,dt}\`. The text and drawing modes share simulation pen-up/pen-down and fixed-pen travel-mark visualization.

The manual drawing pad contains unitless [x,y] input in normalized **canvas-height** coordinates, Y pointing down, so aspect ratio is preserved. The unified planner maps it into a roughly 92 × 60 mm region centered at (155,43) mm. Sharp scribbles may cause mechanical over-acceleration; no online inverse dynamic trajectory optimization is implied.

## API

\`POST /api/plan\` accepts:

\`\`\`json
{"mode":"latin","text":"HELLO","speedMmPerSecond":10}
\`\`\`

or

\`\`\`json
{
  "mode":"hindi",
  "text":"नमस्ते",
  "strokes":[[[0.1,0.2],[0.12,0.21]]],
  "speedMmPerSecond":10
}
\`\`\`

or

\`\`\`json
{"mode":"draw","strokes":[[[0,0],[0.5,0.6],[1,0]]],"speedMmPerSecond":10}
\`\`\`

In Hindi mode the supplied stroke list **must be generated by the browser text shaping + boundary tracing**; the server does not have a Devanagari font or rasterizer, so it cannot turn Unicode alone into trajectories. The API validates the points, solves IK for each point, checks joint range, and stretches segment times toward an indicative 100 half-steps/sec target.

## Physical-hardware safety

The Arduino bridge is still **blocked from pen-down writing** unless \`PEN_LIFT_INSTALLED\` has been enabled on verified, physically calibrated pen-lift hardware. Fixed-pen mode is available **only in simulation**. Even with pen lift installed, the 28BYJ-48/ULN2003 axes are open loop, may skip steps, and have not had acceleration, torque, collision or endstop validation. Do not rely on browser drawing as a safe physical path.

## Limitations

- Text outlines differ from hand-written Hindi and may trace the same contour twice around stroke thickness.
- Very dense or long text is rejected; use short words and large simple drawings first.
- Stroke order from contours is not a handwriting stroke order.
- The 3R model remains estimated from CAD: fit, bearing load and actual pen contact force are not validated.
